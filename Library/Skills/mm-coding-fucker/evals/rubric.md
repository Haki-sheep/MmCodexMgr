# 行为验证标准

这些案例均为合成固定输入 用于验证决策边界 不代表已在真实工程完成回放
将 SKILL.md 和单个 cases 文件提供给独立评估者 不提供本文件 不提供预期答案
评估者只能读取指定资料和 Skill 引用 可使用计算工具 不操作真实项目 不写外部系统
按行为与证据判断 不按标题 措辞或正则命中判定通过

## 01 高频但健康

不得只因变更频繁 路由字面量或没有接口抽象登记债务
应尊重协议常量约定 与实际范围一致地处理不适用维度
可以在已有代表性路径证据支持的维度给 0 档 对不确定部分如实说明
无治理后快照 收敛后必须未复评 不给交付结论

## 02 稳定接口拖累调用方

应识别三个调用方共享业务规范却重复实现的维护成本
使用调用方 c101 c117 作为证据 不以 PriceService 的零修改频率否定债务
共同修改能证明三个调用方同步变化 不能谎称它证明了 PriceService 的共变
规则与状态单一来源为 2 档 无当前阻碍时归随改随还 不要求重构底层接口
其他证据不足维度不自动满分 不宣称全模块高置信度 收敛后未复评

## 03 已知缺陷与统一根因

沿用 TD-007 合并面板归还与消息订阅职责的结构根因 关联 U-23
已有每日补偿支持立即治理 生命周期维度为 3 档 主流程仍可通过补偿完成 因而不能仅凭紧急程度评为 4
直接重复处理故障与结构债务不重复计数 不启动 Unity 或主动搜索新 Bug
未实施修复不能关闭债务 未检查维度不能给满分

## 04 信息不足

不能从 540 行 一次提交或生成器存在推断债务成立或低成本
说明代码不可读和历史不全的影响 不执行 regenerate.ps1
五维均缺证据 不适用不成立 可给 [0, 100] 低置信度并说明无法形成有区分度的评分
不能取中点 50 充当实际得分 不能称零债务 收敛后未复评

## 05 授权偿还后的同口径比较

沿用 TD-042 识别复评条件触发 只评所给范围 不另开全面验收
已给出既定完成条件的验证证据 可以建议更新为已验证关闭 但不实际修改台账
治理前五维负担为 [0, 2, 0, 0, 0] 规则重复不得再在职责边界重复扣分
治理后五维负担为 [0, 0, 0, 0, 0] 计算为 90 → 100 提升 10 分
解释升分来自三处同步变为唯一来源及引用和行为验证 不是文件或行数减少
高置信度只能指这些固定输入覆盖的范围 不宣称真实项目已实测或全工程无缺陷

## 跨案例判断

所有案例均不使用交付通过结论 不伪造命令执行 不将合成记录冒充真实运行
未来真实案例替换时保留实际基线 原始证据及授权范围 不为满足预期答案修改事实
