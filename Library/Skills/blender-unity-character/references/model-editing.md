# 已有模型修改

以用户现有模型为起点 按本次修改目标工作 不默认套用“风格决策 四视图 高模生成 重拓扑 烘焙”的整套从零流程。

## 确定修改面

先检查源模型与用户指定部位 明确本次涉及形体 拓扑 UV 贴图 材质 骨架 蒙皮或 Shape Key 中哪些部分。参考图用于约束本次差异 不因缺少全套四视图就要求重新生成整个角色。

在副本中修改 保留未涉及的对象 层级 命名 材质槽 UV 骨架 蒙皮 Shape Key Action 与来源信息。若修改确实要求改变这些约定 先检查下游依赖 再同步必要引用。

## 按目标执行

- **修形与部件修改** 优先在已有网格上处理 只对确有需要的区域重拓扑 重新展开或烘焙 不自动丢弃整套原模型。
- **UV 贴图与材质修改** 检查对应 UV 接缝 色彩空间和材质连接 新制 Base Color 保持固有色与光照分离 按需制作其他贴图 不顺便重建无关几何。
- **骨架 蒙皮与 Shape Key 修改** 核对绑定姿态 顶点关联 骨骼层级与依赖动作 在实际姿态下检查变形 修改拓扑后确认 Shape Key 和权重仍有效。
- **新增部件** 如果该部件需要独立从零制作且工具选择会实质影响结果 仅为该部件确认制作路线 不重启整个人物的生成流程。

只需要动作修改时转入 [动画制作](animation.md)。模型已经合用而只需 Unity 导入时直接转入 [Unity 交付](unity-delivery.md)。

## 验证

用相同视角比较修改前后与目标参考 按实际影响检查侧背体积 UV 材质或动作采样。只改某个材质不要求重新生成白模 只修局部形体不强制重做全部贴图。

覆盖 Unity 资产前后核对 GUID 子资源与 Prefab 引用 不以成功保存或导出代替实际验证。达不到目标时报告具体偏差 不把局部修改自动扩大成全角色重建。
