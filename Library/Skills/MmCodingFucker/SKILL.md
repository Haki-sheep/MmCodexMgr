# 技术债盘点与治理

## 职责与边界

识别有证据的持续维护成本 输出债务清单 治理档位与前后评分
技术债可以是合理取舍 不能只凭代码风格 复杂度 数值重复或潜在扩展需求认定存在债务

默认只调查和报告 不修改业务代码 不自动建立台账或创建外部任务
用户已授权的修复或台账更新可直接执行 不重复请求授权
本 Skill 不输出通过 条件通过或不通过等交付结论

## 范围与取证

1. 读取当前项目实际采用的规则与相关模块约定 从项目获取工具入口 生成物和既有债务台账位置 不预设语言 引擎或业务目录
2. 声明调查范围与代码快照 有 diff 时记录比较基线和未提交修改 无基线不推断债务引入时间
3. 优先查阅该范围已有债项 再根据用户目标与证据检查相关代码 必要时扩展到直接调用方或资源契约 并说明扩展原因
4. 需要历史热点或共同修改分析时读取 [hotspot.md](references/hotspot.md) Git 历史不足不等于没有债务
5. 仅涉及 Unity 专属契约时读取 [unity.md](references/unity.md) 不把专项检查扩展为全工程验收
6. 在相关修改传播路径和成本已有充分证据时停止扩展 若被缺失信息限制 列出明确缺口 不用扩大扫描替代证据

只消费已有缺陷证据 如 issue 修复提交 回滚记录或已有测量 不主动寻找新 Bug
修复提交聚集只是调查线索 必须核实是否存在共同结构性根因
偶然发现明确故障时单列说明 与相关债项互相引用 不把直接故障和根因重复登记成两笔债
审计不默认执行生成器 迁移 安装或会覆盖工程资产的验证命令 已有任务授权涵盖的操作按该授权执行

## 债务判定与证据

每笔债务必须连接 根因 → 受影响的具体修改或维护活动 → 额外工作或已有运行代价
代码可证明某项修改需要同步多个入口 历史可证明返工重复发生 运行代价则需要已有故障或实测证据
明确区分观测事实与推断 不虚构时间成本 性能收益或历史决策动机

- 已证实 有可定位的结构根因和成本证据 说明证据覆盖范围
- 待验证 根因或成本链尚未闭合 作为候选列出验证办法 不宣称债务已成立
- 信息缺口 无法调查的条件 单独列出 不自动登记为债务

同一根因合并影响位置 不按文件数重复计数
相同字面量必须先确认业务语义相同 直接依赖必须先确认违反实际边界才提出治理
局部重复 更长的函数 或缺少某种设计模式本身不足以证明债务
生命周期与资源归属按实例 租用 绑定等真实周期判断 不把重复绑定机械改成一次初始化

## 治理档位

| 档位 | 进入条件 | 输出要求 |
| --- | --- | --- |
| 立即治理 | 已证实债务持续阻碍当前工作 或已有运行问题需要结构性治理 | 当前成本证据 最小治理范围 风险与先行依赖 |
| 随改随还 | 已证实成本 目前不需单独处理 能明确相关修改触发点 最小治理范围及完成条件 | 触发修改 影响位置 偿还完成条件 |
| 观察 | 候选尚未证实 或尚无法说明可执行的偿还时机与收益 | 复评条件 必要时列缺少的证据 |

近期没有需求计划不自动归观察 能说明下次哪类修改适合偿还时仍归随改随还 触发时再核实成本与风险
先按档位排列 同档位依次考虑当前任务依赖 已证实的重复成本和影响范围 最后比较修复成本与风险
证据无法区分的项目并列 不编造综合排序分数 不因容易修改就排到前面
运行故障的紧急处置与结构治理分别说明 立即治理不等于立即进行大规模重构

## 条目与随改随还

每笔债务采用以下字段 可以用短段落或表格表达 不强制 JSON

- ID 与根因标题 优先沿用已有 ID 新 ID 在当前清单内唯一 不用行号生成身份
- 影响位置List 使用文件与符号定位 行号作为辅助 附代码快照或历史记录引用
- 证据等级与成本 哪类修改变贵 额外步骤发生在哪里 已观察到的频率或规模 未知就注明
- 治理档位与理由 最小修复方向 成本与风险 必要依赖 偿还完成条件
- 状态 待处理 已接受或已验证关闭 已接受需有用户或既有决策记录及复评条件

有可靠比较基线时附来源 本次引入 本次加重或历史 无基线时写来源未知
用户允许复查相关债项时 先按当前需求涉及的位置与契约匹配既有条目
只有当前授权覆盖 且与需求直接相关 范围可控的偿还才并入实现 仅文件相同不代表适合顺手重构
只有完成条目约定的验证才关闭债务 有代码改动但缺少验证时保留待处理并说明进展
已有台账授权更新时复用其格式 无台账时默认只在回复中给清单

## 输出与评分

先简述范围 基线与证据限制 再按治理档位给债务清单
随后列候选 信息缺口 已知故障及执行过的核验 无内容的部分省略
未发现充分证据时明确说明在所查范围未发现已证实债务 不宣称全工程无债务

最后按 [scoring.md](references/scoring.md) 输出债务治理前评分与收敛后评分
评分使用固定维度和负担档位 逐项附证据与评分理由 同时报告覆盖和置信度
它衡量同一范围内的维护负担变化 不替代治理档位 不作为交付门禁
未实施修复或未完成复查时 收敛后评分写未复评 预期收益另列 不用目标分冒充实测分
