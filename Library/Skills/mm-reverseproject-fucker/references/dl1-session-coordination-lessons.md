# DL1 会话经验 协调者与子执行者

用途：逆向参考源码的持续集成需要分派模块、处理证据冲突或判断验证范围时按需读取。本文是当前DL1会话贡献给既有skill的参考资料，入口由创建该skill的会话维护。普通问答和小范围单Agent修改不因此增加协作流程。

来源：本会话已发生的集成、失败修复、暂停与用户质疑。不是其他会话审计，不是对当前磁盘状态的新一轮验证。下文“原因”是基于这些现象的工程分析，不推断执行者的主观动机。历史路径只便于追证，不应写成其他项目的固定目录要求。

## 一 协调者的问题

| 出现了什么问题 | 为什么出现 | 如何解决 | 如何加快速度 |
| --- | --- | --- | --- |
| 对外说“多数动作已经能运行”，并给出约55%的感性进度；实际未做角色模型播放验收 | 把编译、原始动画数据采样、无渲染连续模拟和完整游戏行为混成同一完成口径；没有完整任务拆分和权重 | 已撤回该宽泛结论。报告分别写清原生证据、参考适配、原始动画数据、Unity模型与原游戏实测；无法可靠估计时直接列已闭合链与缺口 | 派发时就写验证层级，最终报告直接消费结果中的范围字段，减少反复解释和错误预期 |
| 旧候选整树带回正式工程，覆盖了已经集成的新变化 | 候选基线落后，把“完整工程可编译”误当成“可覆盖当前正式工程” | 本会话发生过旧B13候选覆盖后恢复。后续只接新增文件与必要修改块；记录基线、正式文件改前哈希和改后结果，冲突由集成者逐块处理 | 让执行者返回最小补丁和新增文件清单；基线相同的独立修改可直接核对，避免整树比较与恢复 |
| 候选CPU PASS容易被当成整个动作已通过 | 原始指令、替身回调、参考身体、完整Owner世界和可见角色不是同一验证对象 | 对照必须说明执行了哪些原始地址、替换了哪些服务、哪些字段未决；主循环检查位置、速度、状态、控制权和拒绝/退出路径 | 为每个候选先约定最小验收场景，先解决会决定设计方向的反例，再扩展案例数量 |
| 多模块公共前缀、时钟、缓存和控制权容易重复消费；Wall后置writer还可能让跳跃晚一帧 | 按动作划分任务，却没有把跨动作的实际调用顺序和写入归属一并约束 | 保持canonical Owner、单一1E0时钟和共享3C/1208缓存。绘出或列出必要调用顺序；明确D4F740内的消费与其后的writer，新增请求按原始时序当帧处理 | 主Agent先固定生命周期和最小接口，把公共状态留在关键路径；子执行者接模块，避免多人各造一套Owner |
| 实例2卡死、无额度且不会回传，成果停留在候选目录 | 任务交付依赖外部会话最终回复，未交付文件与已验证结果边界容易混淆 | 按用户指令停止等待和派发，冻结已有候选后由本地接手；清点缺失输入和实际日志，未编译候选保持WIP | 长任务采用可独立恢复的阶段产物：来源范围、接口、最小差异、首错和下一条可执行命令；回传文字不作为唯一恢复渠道 |
| 证据收集器不接受候选ByteOffset字段，首次追加失败 | 候选字段与收集器输入契约不一致，语义检查晚于候选生成 | 保留第一次失败和冻结候选，在根Agent新收据中按真实语义规范化为FileOffset等受支持格式，再追加 | 分派时提供真实输入样例；先用最小来源条目验证格式，不等整个候选完成才发现schema不兼容 |
| 历史空间查询clear在当前Unknown或后端异常时可能继续影响消费者 | 保存原始历史数据与允许当前帧读取混为一体；后端异常前没有隔离当前活动槽 | 保留历史原值，同时隔离当前未决结果；使用manager捕获的Ready状态；异常保留首错并抛出。已完成非活动查询和显式释放按各自生命周期处理 | 优先测“上一帧clear → 本帧Unknown/异常”的两帧反例，比不断增加正常命中场景更快暴露集成错误 |
| 进展汇报被证据数量、函数数量和PASS数量带偏 | 这些数字容易统计，但无法说明动作资格、进入、多帧运动和退出是否贯通 | 来源数和断言数仅作追踪信息；以可运行链、必要外部端口、未决消费者和实际执行层级作为交付依据 | 维护一份权威范围，每个模块只回报增量与限制；交接链接收据，不重复复制全部历史 |

协调者对正式集成和最终表述负责。子执行者给出错误候选，不能免除集成者核对证据与验证边界的责任。

## 二 子执行者候选中的错误与交付问题

包含当前会话接手的外部执行者候选，不把所有问题归到某个本地子代理，也不把尚未完成的探索自动称为错误。

| 出现了什么问题 | 为什么出现 | 如何解决 | 如何加快速度 |
| --- | --- | --- | --- |
| 旧Type1候选使用SAT后的单个中点表示接触，不能代表原始盒体流形 | 用几何上的合理近似代替原始多接触生产与消费者行为 | 未将该近似当原生完成；接入原始轴选择、面/边裁剪和注册表，检查多个接触对回调结果的影响 | 尽早找“多个接触导致不同消费者结果”的场景；先决定是否必须复原流形，再投入完整世界适配 |
| Walk候选对速度/力提交采用静态快照公式，忽略唤醒回调后的状态变化 | 把外部调用当成无副作用getter，缺少每次读取的时序契约 | 对SetVelocity/AddForce执行原始指令对照；显式回调改变flag/force，调用后按原顺序重读；分支不用的端口保持惰性 | 给每个外部调用列可能写入项；先做一个会改变状态的替身反例，通常比大量常量输入更有效 |
| 速度阈值、浮点操作数顺序与常量存在偏差风险；曾有常量地址标签错误 | 从伪C或数学等价式回推，忽略单精度舍入、NaN分支和实际指令边界 | 对照当前DLL实际指令；保留比较方向、常量位模式和操作数顺序。地址标签错误单独纠正，不能借机改fixture让其通过 | 将定位、提取、执行、比对分开；先覆盖等号、NaN和能产生1ULP差异的输入，再批量扩充样本 |
| 把虚表slot+10的指针getter误读成“kind等于10” | 将偏移、枚举值和返回类型混为一谈 | 根Agent未沿用该DTO；回到调用点、被调用实现和返回值消费，确认指针身份与类型 | 子执行者交付关键接口时附一段真实调用证据和返回值后续用途，避免只交自行命名后的接口 |
| Wall旧候选增加Attribute14E0×Actor88×mode体速系数，CPU测试又只使用系数为1 | 把高度相关辅助量推成速度系数；测试输入使错误公式与原式无法区分 | 独立执行真实调用窗口，48例中44例与旧候选不同，否定该额外系数；不能靠解释变量名保留公式 | 只要公式出现额外乘数，就加入非1、非0的原始观测值；选择能区分竞争解释的案例 |
| Wall CPU夹具把运行时clear向量改为正X，掩盖了原生负X冲量路径 | 测试初始化改变了被验证语义，替身输入变成隐含答案 | 使用明确观测的运行时clear；保留原始符号及连续两次乘2.5的顺序，不能任意合成一次乘6.25 | 测试结果同时记录夹具改写的内存与寄存器；独立审查异常“过于整齐”的方向和单位向量输入 |
| D57870被解释为模型继续播放，实际消费PhysicsBind与actualWalk虚调用 | 函数命名先于接收者身份和消费链确认 | 纠正为实际接收者和slot468判断；None或false的提前返回保持原样，下游读取按需发生 | 首先确认this、返回对象和关键虚调用；语义未知先用地址名，避免错误命名传播到接口 |
| LowStand候选raw190清位分支与原始oracle不符 | 多个相似状态分支被合并，原始分支差异丢失 | 根据失败oracle修正精确分支，保留失败日志，不放宽断言或修改预期掩盖错误 | 在修改共享setter前先测进入、同态重入、正常退出和中断；让每条分支有能区分写入的初始状态 |
| 完整Walk速度helper只看首段函数条目会截断；后续CPU执行遇到未映射内存 | 链式unwind函数范围不止首个条目；所谓getter实际含写入，且读取PE虚拟尾运行值 | 已提取完整8段范围；候选首错UC_ERR_READ_UNMAPPED保留为未完成。继续定位缺失读源与副作用，未观测运行值不能默认为零 | 先验证函数范围、内存读集合和外部服务契约，再批量生成fixture；缺一个关键运行值时先完成其他独立链 |
| 未编译、仅静态分析或仅原生CPU执行的WIP可能被包装成可接入模块 | “代码已产出”“原始窗口已对照”“C#可编译”“正式主循环通过”没有分开交付 | 分别列实际执行项与退出码，未运行明确标注；主Agent按最小补丁集成，再验证正式基线 | 每次交付只给已达成层级与下一处首错；已有成功层不重复全量重跑，只有新改动或未决问题才扩大验证 |

## 三 将经验用于下一次任务

### 分派只约束会影响整合的内容

每个独立任务明确：

- 输入：来源版本与函数范围、当前基线、已有结论及未知端口。
- 可写范围：独占模块或既有隔离区；主循环和公共Owner的修改以最小补丁提案交付。
- 接口：读写谁、坐标系与单位、外部调用副作用、每帧或每生命周期的调用次数。
- 产物：新增文件、必要修改块、证据位置、实际验证结果和未决分支。
- 验收：至少一个贯通场景及会影响该实现的拒绝、退出或中断场景；测试层级与动作范围相称。

按当前用户授权与宿主规则决定是否协作和如何隔离。本文中的历史.scratch路径不是新建临时目录、worktree、会话或外部通信的授权。当前规则限制临时目录时使用允许的位置，正式证据快照按项目约定落盘。

### 优先做能否定错误解释的验证

先选择能让候选与原始行为不同的输入，再扩充样本：

- 回调前后改变flag或force，暴露快照公式。
- 上帧clear而本帧Unknown或异常，暴露过期结果复用。
- 非1系数、零向量、负方向、阈值相等与NaN，暴露夹具掩盖和浮点分支错误。
- 同态进入、动作间切换、事件先解锁后结束，暴露共享状态和时钟重复消费。
- 同一帧后置writer产生请求，暴露新请求晚一帧处理。

原生CPU对照需要列清替身范围。原始指令执行并不自动证明替身参数来自真实运行；自洽测试也不能单独证明原作一致性。

### 验证表述按真实层级填写

| 层级 | 能支持的结论 | 仍需另行证明的部分 |
| --- | --- | --- |
| 静态来源与哈希核验 | 某版本来源中存在指定逻辑与消费关系 | 实际执行、动态输入、最终动作效果 |
| 原始指令CPU对照 | 指定窗口在明确输入和替身下的数值或分支一致 | 完整世界生产、替身真实性、完整动作 |
| C#参考多帧回归 | 指定参考身体和场景中的状态、请求、位移与控制权链 | 原生身体求解和模型表现 |
| 原始动画数据采样 | 指定ANM轨道、事件和时间片段的读取与消费 | 骨骼姿态、混合、穿模、接触与可见播放 |
| Unity角色与场景实测 | 实际接入角色与场景中的表现 | 未覆盖场景及与原游戏的等价性 |
| 原游戏对照 | 已覆盖条件下与原游戏观察的差异或一致 | 条件之外的动作与系统范围 |

不能用上一层通过代替下一层；根据当前任务目标决定需要哪些层。DL1本阶段没有执行最后两层，不能用来源规模或断言数量换算整体完成率。
