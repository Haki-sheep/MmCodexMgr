# 鸭科夫恢复案例：协调者经验

本文件仅归纳本聊天中的协调经历 用于复盘长任务派发 实际验收和交接 不代表项目当前状态 不替代正在创建的主 Skill

## 使用边界

- 依据已发生的行为和回传分析工作流 不推断模型动机或把一次失败归结为能力不足
- 将用户明确要求与本次改进建议分开 本次允许一次返工后接管 不自动变成其他项目的固定重试次数
- 本案例验收目标是接近原版画面并可正常游玩 资源导出和编译通过只覆盖中间阶段

## 1 模型配置未实跑就批量派发

**问题**：用户要求 Cursor Grok 4.7 High 500K 后 同时派发三个任务 并根据管理器返回的配置字符串宣称已经按要求启动 随后全部报错 `Cannot use this model`

**原因**：把帮助文档中的参数语法 支持的最大上下文 和管理器接单回显 当成当前账号及当前 CLI 已接受该组合的证据

**解决**：先用用户指定的完整配置执行一个最小真实请求 核对退出码及运行证据 配置被拒绝就如实报告 不静默改为普通上下文 默认模型或 Auto

**提速**：用一次端到端预检阻断三路相同失败 预检成功后再派发业务任务 若工具不提供实际上下文信息 则明确其未核实

## 2 把中间成果当成用户目标

**问题**：工程打开 编译和部分操作已有进展 但主菜单 背包 设置 人物及场景仍出现白色 黑色或异常背景 用户反复指出画面没有还原

**原因**：验收偏向工具易统计的导出量和编译状态 没有持续以用户要求的画面及完整游玩流程作判断

**解决**：分别记录资源导出 工程打开 代码编译 实际画面和玩法闭环的证据 每一项独立标注通过 失败或未运行 菜单正常不能代替其他面板和场景正常

**提速**：优先恢复一个包含场景 人物 UI 和操作的代表性流程 尽早暴露共性问题 再扩大覆盖范围 百分比只能作为说明依据的粗估 不能由文件数量直接换算

## 3 过早把画面假设说成根因

**问题**：曾把菜单白色区域解释为点光源体积 但关闭相关对象后异常仍在 后续才定位到异常的延迟光照 Shader

**原因**：依据画面形状和场景对象名称推断 没有先检查实际运行状态及渲染过程

**解决**：区分观察 假设和已证实原因 核对 `activeInHierarchy` 材质 实际 Shader 和渲染器配置 每次只改变一个影响因素 以真实帧对比判定

**提速**：同时检查 RendererFeature 全屏及光照 Pass 避免只沿可见 Mesh 排查 本案例的具体线索是 `Hidden/Universal Render Pipeline/StencilDeferred` 不能推广成所有白屏的根因

## 4 反复重启 Editor 和扩张诊断代码

**问题**：小改动多次触发完整 Unity 启动 诊断开关及临时辅助代码不断增加 部分 FrameDebugger 探测耗时后仍无有效事件

**原因**：没有提前规划最小可证伪实验 用长链路试验验证局部猜测 工具能力也未先短测

**解决**：先完成便宜的编译和配置核对 再进入 Play 将能独立还原状态的截图和对比集中在同一受控 Editor 中执行 诊断不可用时记录首错及边界

**提速**：复用已验证的测试入口与证据 输出首错和少量关键状态 保留共享 Editor 的单一控制者 不在用户正在使用的工程上并发启动修改或测试

## 5 管理器状态与实际工作脱节

**问题**：出现接单后无回传 超时以及管理记录丢失 用户看到会话像是停止了 有些工作实际已留下磁盘候选

**原因**：把前端会话状态 管理记录 子进程状态和产物状态混为一谈 没有及时形成可恢复的检查点

**解决**：分别确认已接单 已实际启动 已产出 已回传 已验收 按工具支持等待事件 中断恢复时核对任务专属产物和进程归属 再决定复用 接管或重新派发

**提速**：要求执行者尽早落盘可审查的最小候选 回传首错与下一步 不因管理记录消失就从零重做 也不因超时就假定底层进程已经停止

## 6 工具名及符号存在被误当成接口可用

**问题**：曾混淆同名 CLI 把内部 `Material.rawRenderQueue` 当公开 C# API 使用 也遇到 Unity 版本与验证脚本路径假设不一致

**原因**：靠名称或元数据发现推断调用方式 没有核实可执行文件身份 接口可见性及版本前置条件

**解决**：核对实际工具路径 版本及命令帮助 检查 API 签名和访问级别 先做最小编译或调用验证 脚本适配保留原始错误及修改范围

**提速**：一条廉价调用先排除错误工具链 不用完整工程启动发现基础 API 错误 不通过修改全局环境掩盖路径问题

## 7 派发宽泛 返工继续落在同一失败路径

**问题**：一些任务超时或回交的候选偏离目标 同时启动更多执行者未必形成可集成结果

**原因**：任务没有收敛为能独立执行和验收的单元 失败后未明确区分配置问题 输入不足 技术路线错误和实现错误

**解决**：派发时给出输入 专属可写目录 交付物 验收及禁止的替代做法 把共享工程和 Editor 集成留给单一负责人 返工先补齐具体证据 达到用户约定的返工阈值后由主协调者或合适执行者接管该任务

**提速**：先读已有候选及首错 再接管缺口 不重复调查已经证明的部分 接管只转移失败任务 不冻结原执行者的其他无关工作

## 8 交接必须移交可继续执行的状态

**问题**：长会话上下文过多 用户指定换到“无敌执行鸭B”继续 如果只给进度描述 新协调者仍会重复排查或与旧任务冲突

**原因**：任务状态若只存在对话叙述中 就缺少具体产物 首错 测试入口和独占资源信息

**解决**：交接目标约束 工程路径 已通过和未验证项 已拒绝候选 首错 在途任务身份 可写范围及下一步 核对接收会话身份及接收状态后停止旧协调者的执行

**提速**：交接可直接执行的最小下一步 保留原任务和产物来源 不假定名字相近的 `handoff` 工具就是聊天交接接口 不宣称工具未支持的在途任务所有权转移

## 本案例保留的验收边界

- 本聊天后段已有场景纹理和部分光照恢复的画面 但 UI 面板和人物仍有发白反馈
- 正常拾取有实际操作和物品数量变化证据 不等于战斗 撤离 存档及全场景都验证完成
- Shader 原生编译数据可复用 与恢复出可编辑 Shader 源码是两项不同成果
- 本文件只写入经验参考 不启动已交接的游戏恢复任务 不修改原游戏 用户存档或主工程
