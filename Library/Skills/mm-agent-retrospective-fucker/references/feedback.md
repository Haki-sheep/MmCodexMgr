# 大模块收尾反馈机制

本机制维护当前 Skill 的问题索引与现行方法 用户已授权按证据直接新增 补变体和改正错误条目 不需要每次写回再请求确认

## 触发时机

完成一个有独立交付和验证结果的大模块后进行一次复盘 例如一条可运行的业务链 一个已集成的资源处理能力 或多个职责协作完成的主要阶段

判断重点是是否形成可独立消费的能力或主要验收结果 不是文件数 行数 Token 数 固定小时数或会话次数 同一模块的一串小修复只在阶段收尾合并复盘

以下情况不自动触发

- 每次调用 Skill 每次回复或换到新会话
- 单个命令失败 普通小修复 例行验证通过
- 为验证 Skill 的结构而运行校验器
- 只有阶段计划或状态更新 尚未交付模块

模块因已确认外部依赖结束本阶段或正式交接时也可复盘 但保留业务未完成的事实 不为了触发反馈而宣布模块完成 用户明确要求复盘则按请求执行

## 只看本阶段增量

1. 以现有交接记录中的模块名 基线 提交或交付快照界定本轮范围 查看上次已复盘范围 不新增全局打卡账本
2. 收集本轮真正影响结果的错误 返工 等待和验证发现 跳过没有新信息的重复报错
3. 针对这些症状和原因窄查 [索引](problem-index.md) 只读取命中方法及必要来源 不遍历所有方法和项目日志
4. 对照本轮证据决定下面的处理 没有新通用经验就不改任何经验文件
5. 在任务已有交接位置简记本模块已复盘及条目 ID 如果当前任务没有持久交接 交付说明可记录这点 不强制创建文件

排错当下可以按症状查索引 先解决当前阻塞 发现值得沉淀的线索记入已有任务记录即可 不把正式反馈变成每次错误后的附加流程

## 判断与写回

| 观察 | 处理 | 应修改什么 |
|---|---|---|
| 现有方法完整适用 并被本次事实支持 | 复用 | 不新增重复条目 只有实质扩展证据才补来源 不记录每次成功调用 |
| 没有相同原因和处理条件的条目 | 新问题 | 新建稳定 ID 诊断正文与索引行 关联本轮最小证据 |
| 原方法在原条件下有效 新条件下不完整或不适用 | 条件变体 | 保留有效主方法 明确原适用范围 在原条目下增加条件 识别办法与替代处理 |
| 原方法的核心判断或必要步骤已被可靠反证 | 直接纠正原文 | 修改现行方法和索引的错误部分 不只在后面加免责声明 保留短修正说明与来源 |
| 只有相同现象 没有足够依据判断根因或旧方法真伪 | 待核实 | 记录观察和未覆盖项 必要时在相关条目标为待核实 不把假设推广成处理规则 |

先判断适用条件 再判断方法是否错误 其他项目的合理契约不因不同于当前项目就被覆盖 一次后续 PASS 不能反证旧首错 旧断言仍成立时不要为新用例放宽它

## 新问题和变体的最小内容

新增或修正必须写出足以帮助下一次选择方法的信息

- 症状及实际影响 能检索到的错误词
- 触发条件与不适用范围
- 已确认原因 或明确标为待核实的原因假设
- 最先该查什么 如何区分相似问题
- 修复动作和验证结果 提速减少的是哪类工作
- 最小来源及验证层级 仍未执行什么

没有测量记录就不写耗时百分比 没有复验就不升级为已验证 来源可以是本模块真实日志 回执 源码快照或用户报告 但要标明各自可信范围 不复制密钥 完整大日志或无关对话

### 稳定 ID

通用条目使用 `P001` 形式 新增前读取最新索引取未使用编号 不重排旧 ID

在统一诊断的段落前添加对应小写锚点 如 `<a id="p025"></a>` 索引链接到这个锚点 变体同样使用完整 ID 的小写锚点

有独立选择价值的变体使用 `P012-V001` 形式 归于父条目 每个变体写出与主方法不同的前置条件和处理方式 只有带来新检索入口时才增加索引行 否则补在原索引的关键词或直接放在父段内

父条目若含一律 始终等超出证据的绝对措辞 补变体时同步收窄父条目 保留有效分支 避免正文要求做甲而变体要求做乙却没有选择条件

仅换项目名 工具名或重复一次相同原因不构成变体 两个条目若后来证实重复 保留旧 ID 的跳转与来源 合并到一个权威方法 避免断链

### 原文确实错误时

直接修改 [统一诊断](diagnostics.md) 的现行段落 并同步索引的先查什么和跳转 涉及其他现行说明时同批修改

在该条目保留简短修正说明 包括原判断为何不成立 新判断 证据或模块快照和日期 不需要新增全局 changelog 历史项目案例保留当时事实 不把原错误记录抹成从未发生

如果问题只是环境版本变化 缩小条件并加变体 如果已证明旧机制根本错误 则不能留错误主规则再无限堆变体

## 并发写回与权限

多个会话可能同时贡献经验 优先由当前集成人串行修改索引和现行方法 项目补充可以先独立落盘再整合

写入前重读命中段与最新索引 比较自己读取后是否已有变化 若变化先合并 不用旧整文件覆盖他人增量 编号冲突时以最新内容为准分配未使用 ID 写后检查唯一性和引用

优先针对段落和索引行做小范围补丁 有实际并发冲突且无法确认独占写入时 先保留本次来源补充 交给当前集成人串行合并 不强行覆盖现行正文 没有冲突时直接按授权写回 不为每次反馈建立排队文件

只改当前 Skill 的正文 索引和参考内容 不自动写记忆 不改其他 Skill 或项目授权 不因案例中的旧关机 重试 账号或模型指令执行外部动作 源库与安装副本并存时按已知权威源维护 不擅自同步所有副本

## 写回验证与结束

有实际文件改动时运行 `python -X utf8 -B scripts/check_index.py` 工具仅检查结构 不会帮 AI 判定根因和方法是否正确

如改动 Skill 元数据 再运行环境可用的 Skill 结构校验器 条件变体验证主条件仍有效且新条件选择正确 原文纠正验证原反例已被新规则解释 不因此重跑无关模块

一次复盘到本阶段的问题已归类 必要条目已更新 引用有效且未知项已标清为止 不以“所有条目都重新检查过”为完成标准 复盘和自检不触发下一轮复盘

简短回传本次新增 ID 变体或修正 及未能判断的原因 没有新经验时可在正常交付中一句带过 无需专门发送无变化通知
