# 执行者经验

这是首轮按角色整理的来源记录 当前出问题先查 [问题索引](problem-index.md) 现行方法与后续纠正维护在 [统一诊断](diagnostics.md) 不需要每轮通读本文件

执行者的质量取决于结论能否被重现以及是否守住支持域 不以话说得肯定 检查数量或单次 PASS 判断

## 已发生的问题与改进

| 问题 | 为什么出现 | 如何解决 | 怎么加快速度 |
|---|---|---|---|
| W1 把析构清零解释为构造默认值 | 只看字段写零与虚表安装 没查函数调用方和资源释放语义 | 核对分配与构造调用 删除包装器 析构及复位路径 保留原始片段但撤回错误推论 | 先查生命周期直接调用点 比继续扩大零值回放更快排除错误方向 |
| W2 有限检索未命中就推断不存在写入者 | 写指令操作数解码有遗漏 又把部分编码扫描当成完整搜索 | 修正解码 为已知写入准备正例校验 记录直接写 别名 间接调用和初始化表的覆盖范围 | 按已知位移 函数范围 虚表引用和直接调用缩小检索 使用能够改变下一步决策的搜索 |
| W3 正常输入通过 接收者更换时仍错误返回 | 将世界身份稳定等同于查询接收者稳定 忽略回调期间对象变化 | 在原指令要求的位置重读当前对象 验证其生命周期及身份 再提交结果或分配配对 | 优先跑会替换接收者的反例 早于大量稳定场景回归 |
| W4 隔离构建漏已有依赖 | 只复制目标文件 没核对它引用的程序集 资源与项目设置 | 明确引用既有依赖 保留首次编译错误 只修测试环境 不改业务以迎合编译 | 先最小构建再跑样本 环境正确后复用 不反复创建不同版本的隔离工程 |
| W5 产物存在但回传协议失败 | 要求最终回复为严格 JSON 却带尾随文字或损坏 UTF-8 字节 | 使用工具规定的结构和编码 进度信息与最终机器回执分开 保留协议失败与产物验证的不同状态 | 确定性序列化并在本地解析一次 避免管理器因格式失效而重新执行已有工作 |

W1 至 W3 属于推理或实现问题 W4 属于执行环境 W5 属于交付协议 网络断连与模型目录不可用还需另外归类 不据此给模型排质量名次

## 分析前先固定输入与生命周期

从用户可观察的结果倒查首个未闭合生产者 不从整份大反编译文件开始

对关键对象写明

- 从哪个参数 字段 虚槽或返回值取得
- 是入口捕获对象 还是某次回调后重读的当前对象
- 谁分配 谁拥有 谁替换 谁释放
- 哪些条件只是请求成功 pending 已构造或已激活

命名表达已证明的职责 不要求恢复原始变量名 还没证明是镜头 控制器或物理记录时保留结构性描述 不让名字替代证据

遇到写零不要先判定初始化 遇到非空指针不要先判定对象有效 遇到真实函数地址不要先判定完整虚派发

## 检索与回放的支持域

检索报告说明目标 指令或引用种类 函数与字节范围 结果和遗漏 未命中只能支持已查范围的未命中

运行验证区分以下事实

| 观察 | 能支持的结论 | 不能顺带推出 |
|---|---|---|
| 手工布置字段后直接调用真实叶 | 该叶在该输入上的行为 | 原调用方或虚表初始化已执行 |
| 单个模拟器保留同一对象 分多次进入函数 | 同对象分段组合行为 | 被跳过的中间路径已闭合 |
| 从入口单次连续执行到断点 | 该前缀的真实顺序与副作用 | 断点之后或完整帧已通过 |
| 本机 CPU 执行部分原指令并桥接外部调用 | 原指令段与所列桥接输入下的行为 | 桥接内部逐指令等价或所有寄存器副作用等价 |
| 托管实现对齐原回执 | 已列夹具和支持域的对应关系 | Unity 实测或原游戏全链已验证 |

特别核对

- ret 夹具可能保留旧 RAX 不能据此当作真实 getter 返回值
- arena 的零填充不代表原运行期默认值 realloc 保留旧前缀与重新分配清零不同
- 给定记录类型和真实构造得到记录类型不同 可能改变是否进入唤醒等关键分支
- 初始化中途停止时 即使部分字段已写 也不能称完整初始化成功
- pending 返回不代表已经有可消费身体 正常返回不等于所有后续动作已运行

## 写实现与检查

优先复用正式内核 在候选中补缺口和适配 不重写一套同名逻辑来证明自己正确

- 按原语义保留动态重读和捕获顺序 不为简化接口把多次当前对象读取合并为一次
- 资源提交失败 释放失败和后续业务失败分别验证 不擅加 finally 释放 重试或恢复改变原行为
- 原函数在失败前已完成的写入保留并检查 不只检查最终返回值
- 受控端口标明输入 输出 副作用及未知实现 不把未知资源解析替换成空函数或默认成功
- 先用少量分支改变 旧新对象 列表数量及空绑定反例验证契约 再增加能覆盖新行为的样本
- 稳定范围内复用已有原回执 新组合增加组合检查 不把每个新测试都写成一次全工程重跑

## 最小交付

使用现有回传协议或任务格式 包含下列必要信息即可

- 本任务增量和正式基线 输入及关键来源哈希
- 可原样执行的验证入口 工具版本及实际依赖
- 每条检查的真实结果 首次错误和修正 最终失败也完整保留
- 接收者身份 动态重读 资源归属及关键失败前缀
- 已覆盖范围 未执行部分 首个未闭合依赖与建议接续

执行前核对脚本副作用 临时内容放到允许的临时目录 可写范围与共享资源契约不因失败而扩大

发现输入缺失或边界冲突时给出具体缺口 能独立完成的部分继续推进 不能用猜测补齐后汇报完成
