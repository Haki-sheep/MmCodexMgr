# 统一诊断方法

这里维护现行方法 按问题 ID 定位读取相关段即可 项目案例保留原事实与适用条件 不自动升级为所有工程的规定

## 协调与验证

<a id="p001"></a>
### P001 状态与完成事件脱节

先对齐任务身份和实际阶段 分别看已发送 已开始 已产出 已回传 已复验 已集成 不用前端 Running 或接单回显替代执行证据

产物已完成则先恢复待验收结果并修正现有账本 不重复派发 完成事件无法继续主会话时如实标记空档 不声称一直后台推进 原因未查明就不归因于模型停止工作

提速先减少完成到验收的等待 使用现有事件或当前任务的有界等待 不为一个任务另建定时监控

来源 [协调者 C1](coordinator.md) [超时和交接案例](duckov-coordinator-lessons.md)

<a id="p002"></a>
### P002 指定模型或执行配置不可用

核对实际账号 可执行文件 版本 完整选择器以及用户指定的上下文和推理规格 名称在列表中 管理器回显配置或认证健康都不足以证明该请求已经运行

需要批量启动时先用一个最小的已授权业务单元确认配置 已有同条件成功记录可复用 不为每次调用额外产生健康检查模型请求 配置被拒保留原错误 不静默降级到短上下文 Auto 或其他账号

TLS 与元数据加载失败单独诊断 一次报错不能证明额度耗尽 停止或重试仍遵守用户明确策略

来源 [鸭科夫协调 1](duckov-coordinator-lessons.md) [DL1 工具链案例](dl1-cases.md)

<a id="p003"></a>
### P003 工具链 依赖和编码不匹配

先最小构建核对 SDK 目标框架 API 可见性和程序集引用 构建后还需核对运行所需的夹具 资源及 Content 输出项 不用编译通过代替打包或运行依赖验证

中文交付核对实际文件编码与读取编码 明确 UTF-8 必要时只对当前验证进程设置编码 保留首错 不修改全局环境掩盖问题 不删业务调用或增加空实现凑通过

提速先修最早的环境缺口 再进入完整运行 不针对同一个环境失败反复启动昂贵宿主

来源 [协调者 C2 C3 C7](coordinator.md) [执行者 W4](executor.md)

<a id="p004"></a>
### P004 工具能力与授权不匹配

承诺验证前核对真实接口 签名 访问级别 可用协议及权限 用廉价调用确认能力 符号存在或工具同名不代表功能可用

区分纯能力不支持与明确禁止绕过 前者可在授权范围选择合法替代 后者不换端口 协议或工具规避限制 替代检查只能报告自身实际范围

来源 [鸭科夫协调 6](duckov-coordinator-lessons.md) [浏览器验证边界](dl1-assets-logic-coordinator.md)

<a id="p005"></a>
### P005 验收口径超出证据

把用户目标和每份回执的 Scope 未执行项对照 资源导出 编译 模拟回放 真实场景输入 画面及完整流程分别判断 用户目标本来是 mock 时也不擅自扩成实机验收

同一对象分段执行不等于中间路径已运行 测试组数 向量数和重复复跑不相加成新增能力 正式文档只在相应验证结束后提升状态

用户要求百分比可给标明口径的主观估值 没有统一分母不伪装成精确验收率

来源 [DL1 评分与文档案例](dl1-assets-logic-coordinator.md) [鸭科夫协调 2](duckov-coordinator-lessons.md)

<a id="p006"></a>
### P006 实现或验证方法偏离用户目标

先核对允许的刺激和替代方法 调用内部回调或修改状态可以验证内核 但用户要求正常游玩时不能用它替代真实输入 路径和业务事件

无法完成的阶段保留未通过 不自行省掉验收条件 先用一小段合格流程确认方法 再写长路线

来源 [鸭科夫执行 1 2](duckov-worker-lessons.md)

<a id="p007"></a>
### P007 任务过宽 互等与接管成本

按可独立交付的能力切分 明确输入 基线 专属可写范围 产物 验收和共享资源归属 需要持续共同改同一批文件时优先串行 不为人数拆任务

接管先读取已有增量和首错 只转移失败任务 不冻结无关工作 返工次数按当前用户或项目约定执行 启动恢复不与实现返工混计

来源 [鸭科夫协调 7 8](duckov-coordinator-lessons.md) [执行者检查点](duckov-worker-lessons.md)

<a id="p008"></a>
### P008 重复回归与昂贵试验

先问是否有新变更 新失败或新疑点 相同来源 字节范围 输入 环境与支持域的已接受证据可复用 新的身份和时序组合仍要组合验证

围绕最容易推翻假设的反例设计最小试验 能复用已确认状态的宿主则复用 明确其独占与恢复责任 必要整体检查通过后停止重复跑相同内容

来源 [协调者验证安排](coordinator.md) [鸭科夫协调 4](duckov-coordinator-lessons.md) [重复催问案例](dl1-assets-logic-coordinator.md)

<a id="p009"></a>
### P009 文档 来源与导航漂移

核对权威入口 源码快照 哈希和实际验证回执 预期通过数量与已运行数量分开 来源改变先重核受影响证据 不沿旧布局继续推论

详细事实只维护一处 其他入口链接到它 大量产物需要导航时区分成品 原始池 旧迭代和证据 不能用堆叠全文件名单代替检索入口

来源 [DL1 协调文档与索引案例](dl1-assets-logic-coordinator.md)

## 推理与实现

<a id="p010"></a>
### P010 生命周期与对象来源误判

从直接调用方及资源归属确认构造 析构 复位和运行期写入 写零与安装虚表都不是单独的构造证据 命名只表达已经证明的职责

入口为直接叶调用就只报告该叶行为 构造中途停止时不能宣称表安装或虚派发完成 映射零值与给定字段不能当作运行期生产者

来源 [DL1 生命周期与真实发布案例](dl1-cases.md)

<a id="p011"></a>
### P011 有限检索与证据对象误用

先用已知写入或引用作正例核对解码 再按位移 函数范围 虚表和直接调用缩小搜索 未命中只说明已查范围 未覆盖的别名 间接写和初始化表仍未知

有界片段允许存在明确记录的外部控制流边 完整复制函数则要覆盖实际函数分片和所需边界 区分验证对象后调整检查 不放宽关键语义断言凑 PASS

来源 [执行者 W2](executor.md) [AI 摘录外部边案例](dl1-assets-logic-executors.md)

<a id="p012"></a>
### P012 动态接收者与重读时序

先从原语义或接口契约区分入口快照与当前对象 对原本要求在回调后重读的字段保留重读 对契约明确要求捕获的对象保留捕获 不统一缓存也不统一改成读最新

用回调替换接收者 配置或列表的反例检查提交对象与资源归属 世界身份不变不代表接收者身份不变 单个函数分别通过也不能证明跨函数同帧顺序

来源 [DL1 接收者反例](dl1-cases.md) [两次查询不可合并案例](dl1-assets-logic-executors.md)

<a id="p013"></a>
### P013 提交 释放与失败前缀

标出事件游标 资源所有权和已产生副作用的提交点 发送成功与接收业务成功可能不是同一个事务 重试前先确认原语义是否允许重复

保留失败前已经完成的写入 未定义恢复策略时不加回滚 重投或 finally 释放来改变原行为 修复必须有相应契约 验证提交后抛异常与释放失败等会改变责任的反例

来源 [战斗事件失败契约](dl1-assets-logic-coordinator.md) [慢路径释放顺序](dl1-cases.md)

<a id="p014"></a>
### P014 首错无法复现

保存首次实际数值 输入 源码 环境及前置状态 缺失的测量值不能补成猜测值 只有后续通过而无根因证据时保留原因未知

必要重跑用于判断复现性 采用有界次数和明确问题 不改阈值 换工具链或反复跑到通过 即使怀疑预热 JIT 或 GC 也先验证而非直接归因

来源 [DL1 零分配失败及重复观测](dl1-assets-logic-executors.md) [协调收尾边界](dl1-assets-logic-coordinator.md)

<a id="p015"></a>
### P015 部分消费与状态边界隐藏

区分已解析 已应用 未消费和明确拒绝的内容 必要时把未应用属性或子节点暴露给调用者 不能吞掉后让调用者误以为完整执行

pending 请求 已有记录 已构造身体及已激活是不同状态 未知算法保留显式依赖和范围 不以默认 true false 或空函数补全业务

来源 [Buff 子集消费案例](dl1-assets-logic-executors.md) [物理记录状态边界](dl1-cases.md)

<a id="p016"></a>
### P016 输入或交互不可达

检查焦点 游戏是否消费输入 输入轴或角色位移 以及当前 UI 阻断 对方法和事件还需查可见 激活 可交互及状态允许条件

先验证打开 操作和关闭的短流程 游戏状态变化后重新同步输入 测试专用焦点设置按归属恢复 不用增加等待时间解决永久隐藏入口

来源 [鸭科夫执行 1 4](duckov-worker-lessons.md)

<a id="p017"></a>
### P017 坐标 单位 进制或版本解释错误

输出数值时标明坐标空间 单位 进制和来源版本 世界位置取得真实 Transform 或使用完整父链变换 不把局部位置直接用作世界位置

机器偏移或枚举名称不能跨 DLL 版本套用 未知字段不靠猜名字补业务意义 先核对代表点和代表键 再批量生成路线或教材

来源 [鸭科夫执行 3](duckov-worker-lessons.md) [AI 进制与版本案例](dl1-assets-logic-executors.md)

<a id="p018"></a>
### P018 资产落盘 加载与视觉结果不一致

按需要验证真实文件 保存重载 依赖解析 多工件共存与实际运行管线 内部名称冲突确认后再做唯一化并核对引用 不把 API 返回等同于持久化

画面异常先区分观察和根因 用代表资产及单变量帧对比核对材质 Shader 和实际 Pass 不用特定项目的白屏原因解释所有异常

来源 [鸭科夫执行 7](duckov-worker-lessons.md) [鸭科夫协调 3](duckov-coordinator-lessons.md)

<a id="p019"></a>
### P019 热路径复杂度与分配

先确认实际热点和测量环境 再检查重复列表搬移 数组输出 接口枚举和容量增长 多项删除可考虑稳定压缩与一次移除 输出可考虑由调用方复用

验证交错存活项等正确性边界后在同条件测成本 一次 .NET 零分配观测不是 Unity 全场景预算保证 不为无症状路径开展额外重构

来源 [DL1 属性执行热路径](dl1-assets-logic-executors.md)

<a id="p020"></a>
### P020 长链路前置阶段从未通过

找到最早失败状态 为每段定义实际入口和到达条件 修复前段后复用已通过输入再往后推进 不反复运行尚不可达的后半段

先做可代表用户目标的一小条完整流程 再扩展规模 局部编译和内部状态变化不替代用户要求的运行阶段

来源 [鸭科夫执行 8](duckov-worker-lessons.md) [鸭科夫协调 2](duckov-coordinator-lessons.md)

<a id="p021"></a>
### P021 搜索提示与实际检索字段脱节

检查用户提示中的词是否进入实际检索字段 区分字面路径匹配 命名线索与关键词搜索 不把 UI 提示等同于已经可搜索

直接使用提示词验证主入口 找不到的词以及清空恢复 必要时增加显式关键词 别只检查生成文件结构和路径存在

来源 [DL1 项目目录搜索案例](dl1-assets-logic-executors.md)

<a id="p022"></a>
### P022 结构化回传失败

保留原始字节与解析错误 核对最终格式 编码和尾随内容 进度消息不要混入要求严格 JSON 的最终回复 用确定性序列化和本地解析检查

磁盘产物可独立恢复验收 但管理器的协议失败与本地恢复结论分别保留 不重写失败历史 或在投递不明时重新启动相同工作

来源 [执行者 W5](executor.md) [回传故障案例](dl1-cases.md)

<a id="p023"></a>
### P023 恢复动作与实际状态不匹配

先核对已开始 投递失败 投递不明 实例退出 阻塞和已完成 超时不证明进程已停止 恢复入口必须满足当前工具的实际前置条件

投递重试保留原身份 返工按工具契约关联原任务 不为绕过占用另开重复执行者 取消或清理前确认任务拥有的资源与目标范围

来源 [协调者 C4](coordinator.md) [鸭科夫协调 5 8](duckov-coordinator-lessons.md)

<a id="p024"></a>
### P024 经验方法不适用或需要补充

先查症状以外的关键条件 包括任务目标 输入契约 版本 资源归属和验证层级 判断新事实是原条目的新实例 条件变体 新根因还是对原方法的反证

排错期间可以按需查阅和记录线索 正式经验写回集中到大模块收尾 按 [阶段反馈机制](feedback.md) 选择不变 新增 变体 修正或待核实 不在每次会话执行全库检查
