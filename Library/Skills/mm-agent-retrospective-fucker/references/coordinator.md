# 协调者经验

这是首轮按角色整理的来源记录 当前出问题先查 [问题索引](problem-index.md) 现行方法与后续纠正维护在 [统一诊断](diagnostics.md) 不需要每轮通读本文件

协调者的首要职责是让被验证的成果进入用户需要的实际调用链 并如实维护当前状态

## 已发生的问题与改进

下表对应 DL1 已观察到的问题 案例编号见 [证据定位](dl1-cases.md)

| 问题 | 为什么出现 | 如何解决 | 怎么加快速度 |
|---|---|---|---|
| C1 执行者交付后仍停留在运行中 成果未及时复验集成 | 已确认产物时间与账本不一致 完成事件是否未唤醒 排队或未消费尚未查明 | 接续先对照任务状态 产物时间及完成回执 把可复验成果送入验收 修正现有账本 | 观察完成到验收的等待时间 优先处理阻塞后续的已完成候选 不继续给已完成任务重复派发 |
| C2 正式构建通过 运行却找不到新夹具 | 集成只加代码与调用 漏了项目显式 Content 复制项 | 将源文件 项目配置 夹具与入口作为同一集成单元 保留 FileNotFound 首错后补配置复跑 | 集成前检查产物依赖闭包 避免跑完整回归后才发现缺文件 |
| C3 交接工具链和依赖没有固定清楚 | 工作区需要的 SDK 与系统默认 SDK 不同 隔离项目也可能漏已有程序集引用 | 交接实际可执行文件路径 版本 目标框架及必要依赖 先核对副作用再运行 | 用最小构建先排环境问题 不把编译环境缺失扩成业务排错 |
| C4 模型参数被拒后 恢复动作不适用任务状态 | 未先区分启动失败 实例退出后的阻塞与投递不明 | 保存原 request_id 与错误 根据工具允许的状态恢复 不把 failed 一律送入只支持 blocked 的续跑接口 | 做一次有界诊断 避免无效恢复循环 精确模型不可用时报告限制 并在授权内推进独立工作 |
| C5 把已定位的真实叶调用写成完整虚派发 | 静态虚表定位与直接执行叶函数的证据被合并理解 构造后半及表安装尚未执行 | 回执明确入口调用方式 构造断点与同对象身份 文档同步收窄 | 在验收边界一次发现措辞越界 避免后续模块沿过强结论开发 |
| C6 给出整体百分比却没有可复算的分母 | 用户需要直观估算 但当前记录主要按函数和证据批次组织 | 用户要求时可以给粗估 明确参考工程 Unity 实机验收的口径与主要剩余链 | 平时围绕动作链是否闭合汇报 不用增加文件或检查数量制造进度 |
| C7 中文交付文件与验证工具编码不一致 | 生成器沿用系统编码 编辑工具写 UTF-8 校验器又按默认编码读取 | 明确文件编码 统一 UTF-8 验证脚本在当前进程启用 UTF-8 不持久化修改全局环境 | 在完整校验前核对生成文件可被目标工具解码 避免把编码故障当成内容错误 |

## 派发前固定最小契约

复用已有任务记录 提供本轮所需内容即可

- 目标 是调查 实现 复验还是集成 明确完成后哪条调用链能够继续
- 基线 正式版本或文件清单 来源哈希 当前已验证范围与未通过候选
- 输入 已有摘录 实际 SDK 关键资源与依赖 以验证过的真实路径为准
- 范围 独占可写目录 只读共享资源 集成人 其他任务依赖
- 交付 本任务增量 可复跑入口 首错 支持域 首个未闭合依赖
- 停止条件 用户指定的超时 额度 返工上限及工具不可用边界 不从案例自行增加新的固定次数

并行写入按工程要求隔离 未获准创建 worktree 时选择只读分析 临时候选或串行实现 不绕过隔离规则

## 验收与复验成本

候选验收先回答三个问题

1. 候选解决的是当前关键缺口吗 是否带入旧工程或无关变更
2. 新结论最容易被哪个反例推翻 来源和试验环境能否复现
3. 哪些证据已被接受且可复用 哪些新身份 时序和集成关系必须另测

证据复用应同时匹配来源及字节范围 输入夹具 工具链与影响结果的运行库 配置和支持域 缺一个关键条件就不要静默复用

没有语义变化的重复原生回放通常可省 跨函数的新组合不能只引用各函数分别通过的记录

局部变更完成必要验证后集中集成 执行与风险相称的整体检查 新变更 新失败或未解决疑点才扩大或重复测试 不规定每个小批次都跑全套

## 状态漂移与故障恢复

- 工具返回已接收不代表执行者已开始 交付不代表通过 通过不代表集成
- 执行者结束后核对完成事件与实际产物 若主会话没有被继续唤醒 不声称工作一直在后台推进
- 不同工具对超时与取消的语义不同 先确认实际进程和投递状态 不重复启动或取消无关任务
- 相同请求的投递重试保留身份 修改任务或返工按实际工具规则建立新记录 并关联原任务 不用新标识绕过投递不明
- 启动恢复和质量返工分开记录 传输失败且业务未开始 不直接算一次实现返工
- 恢复不可用时保全产物 在用户授权与预算内选择当前会话或已有执行者接手 不悄悄更换指定模型 上下文规格或账号

## 关键路径与等待管理

不要把 TLS 通用资源管理或完整引擎启动都当成当前动作的前置任务 先判断用户需要的是原游戏全链验证还是明确端口支持下的参考实现

- 核心资格 状态迁移 动作算法保持在实现内 不能改成外部布尔成功
- 时钟 分配 资源解析等服务可按工程契约显式隔离 验收只覆盖实际实现范围
- 分段回放可以推进研究 记录每个重新进入点 没执行的中间段不算连续闭合
- 当多个任务持续互相等对方输入时 先收敛一个最小共同契约 再决定串行或并行 不额外加代理来掩盖依赖

没有时间记录时只说预计减少哪类工作 不编造节省比例 有记录时优先区分执行 失败重跑 等待验收和集成耗时
